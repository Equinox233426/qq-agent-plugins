# 画图委派（image-delegate）

让机器人**用别的模型画图**，聊天用的主模型一个字都不改。

0.4.0 起**不再让你重填 URL 和 Key**：接口来源就是软件里已经接好的那些 ——
你在「设置 → 模型 API（模型管理）」里配过的提供商与模型，技能直接拿来用，
自动挑出像画图的、按顺序接力。

---

## 一、它怎么挑接口

按这个顺序组候选，逐个尝试直到出图：

1. **软件里的提供商**（`config.providers`，顺序 = 模型管理里的顺序）
   —— 每个提供商只出**一个**候选：里面最像画图的那个模型
2. **主模型那套**（`config.api`）—— 只有它的模型看着像画图模型时才算
3. **补充接口**（技能设置里的三项，一般不用填）—— 位置在最后

「像画图模型」的判据是名字特征：认得 `gpt-image` / `dall-e` / `flux` / `seedream` /
`nano-banana` / `qwen-image` / `kolors` / `sdxl` 这些，并**排除** `chat` / `vision` /
`embedding` / `whisper` / `tts` / `rerank` 这类明显不是画图的。

为什么每个提供商只出一个候选：否则一个站点里挂 5 个画图模型，失败时会在同一个站点上
白试 5 遍。要更细的控制就用下面两个设置项。

---

## 二、装到哪

```
<你的 QQ Agent>/resources/app/skills/image-delegate/
├── skill.json
├── index.js
└── README.md      ← 本文件（加载器不读它，删掉不影响运行）
```

拷进去就生效（热重载默认开，`enabledByDefault: true`）。它提供两个工具：

| 工具（模型看到的完整名） | 干什么 |
|---|---|
| `image-delegate__draw` | 画图并直接发到当前会话 |
| `image-delegate__models` | 列出"会按什么顺序用哪些接口"（只读，不产生生成费用） |

技能目录必须是 `<app>/skills/<id>/` —— 它靠 `../../src/config.js` 和
`../../src/providers.js` 读软件配置（见第五节）。

## 三、配置（大部分留空就行）

| 设置项 | 默认 | 什么时候动它 |
|---|---|---|
| **只用这些提供商** | 空 | 只想用其中几个：填名字或 id，逗号分隔，**顺序按你写的来** |
| **优先模型** | 空 | 想让某个模型排前面：填模型名或名字片段，如 `gpt-image-1, flux-schnell` |
| **失败接力级别** | `safe` | 见下一节 |
| 默认尺寸 / 提示词后缀 / 单次最多几张 | — | 按需 |
| 返回格式 / 额外请求字段 | auto / 空 | 接口报「不支持 response_format」或要 `modalities` 时才动 |
| 超时 / 重试 / 体积上限 / 留档张数 | — | 机器慢、图大时调 |
| 补充接口（Base URL / Key / 模型 / 形态） | 空 | **只有当画图模型没法加进模型管理时**才用 |

### 必懂的开关：「失败接力级别」

| 级别 | 什么时候换下一个接口 | 代价 |
|---|---|---|
| **safe（默认）** | 只在**确定没被受理**时：连不上、4xx/5xx、429 | 不花冤枉钱，但偶尔"图没出来就是没出来" |
| **aggressive** | 连**结果不确定**也换：超时、响应读到一半断、返回 200 但没图 | 出图最稳，但那一发可能已经计过费，换接口＝再花一次钱 |

每次接力都会在日志和给模型的回复里写明理由，不会悄悄换。

## 四、怎么用

群里正常说人话：

> 画一张猫娘
> 帮我画个赛博朋克风格的街道
> 来三张落日下的鲸鱼

**画图** `image-delegate__draw`：`prompt`（必填）、`size`（可选）、`count`（可选，1~4）。

**查接口清单** `image-delegate__models` —— 直接问机器人：

> 画图能用哪些模型
> 画图接口配好了吗

它会把"按什么顺序、用哪个提供商的哪个模型"列出来，并说明哪些提供商没找到画图模型；
加个 `all=true` 还能把所有已接入的模型都列出来（往「优先模型」里抄名字时很方便）。

问"画图没反应/画不了"时，技能会直接告诉你三条补救路径（去模型管理拉模型列表 /
填优先模型 / 用补充接口），不会只说一句"失败"。

## 五、它为什么不自己读 config.json

因为读不对，也不安全：

- 数据目录有四种可能：安装目录 `data/`、项目 `data/`、多开时的 `data-2`、
  `QQ_AGENT_DATA_DIR` 指定的目录 —— 自己拼路径必然漏掉某一种。
- 提供商的 Key 已经从 `providers[]` 挪到了 `config.dshProviderKeys[providerId]`，
  自己读原始配置只会拿到 `******` 掩码；`currentProviders()` 才会解出真实 Key。

所以技能用相对路径 `../../src/config.js` / `../../src/providers.js` 问本体要配置
（相对本文件解析，和 app 装在哪儿无关），拿到的还是内存里的实时配置 ——
你在模型管理里加了接口，不用重启技能就能用。

**它只读、不写**：源码里没有任何 `updateConfig`/写配置的动作，
也不碰 `api.model` / `fallbackModels` / `visionModel` / `videoModel`。
这两条有静态检查盯着（`test/image-delegate-test.mjs`）。

## 六、出错怎么办

| 看到的报错 | 真正的原因 | 怎么办 |
|---|---|---|
| `软件里已接入的接口中，没有找到画图模型` | 模型管理里没有画图模型 | 照报错里的三条路走（最常见是去模型管理拉一次模型列表） |
| `「图片接口」返回 HTTP 404` | 这个站没有 `/images/generations` | 形态填 `chat`，或交给 auto 让它自己退 |
| `返回 HTTP 401 / 403` | Key 不对 | 去模型管理里重填该提供商的 Key；接力会自动试下一个 |
| `返回 HTTP 429 / 5xx` | 限流或上游挂了 | 会自动接力；也可以稍后重试 |
| `接口超时（N 秒没返回）` | 模型太慢 | safe 下报错；想自动换接口就调 aggressive |
| `读取接口响应中断` | 网络断了一半 | 同上；这一发可能已计费 |
| `接口没返回图片。原始响应：…` | 模型名不对，或该模型不做图 | 用「画图接口清单」看真名，或把它从候选里排除 |
| `图片超过体积上限 NMB` | 出图太大 | 换小尺寸，或调大「图片体积上限」 |
| `拿到的不是图片（可能是防盗链页…）` | 图床给了 HTML | 换接口，或让它返回 base64 |
| `图画出来了但发送失败：…` | 协议端到 QQ 的链路问题 | **别重新生成**（白花钱），把原因告诉群友 |

## 七、已知边界（诚实清单）

- **找不找得着画图模型，取决于它在不在你的模型列表里**：没拉过模型列表的提供商，
  技能看不到它的模型 —— 去模型管理点一次「拉取模型列表」即可。
- **只做文生图**：不支持图生图 / 参考图 / 局部重绘 / LoRA / 工作流。
- **每个提供商只出一个候选**（要更多就填「优先模型」逐个点名）。
- **接力按顺序**，不支持按延迟/成本智能排序。
- **需要在真接口上验一次**：离线脚本用假 app + 假接口把逻辑跑通了（74 项），
  真接口的参数差异只有你自己的 key 能暴露。
- 要「先把需求交给文本模型改写成专业提示词，再画」那种**两跳**流程：
  现在是原样透传，需要的话说一声。
